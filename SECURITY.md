# Security Policy

## Supply Chain

Sentra is a security-focused language, and we hold our own release pipeline to
the same standard.

Every official release (starting with v0.0.1) is:

- **Built from source in CI** — binaries are produced by the public
  [release workflow](.github/workflows/release.yml) on GitHub Actions, never on
  a developer machine.
- **Checksummed** — `checksums.txt` contains SHA-256 digests of every artifact.
- **Signed** — `checksums.txt` is signed with [cosign](https://github.com/sigstore/cosign)
  using keyless (OIDC) signing, so the signature is bound to the exact GitHub
  Actions workflow run that produced it.
- **Accompanied by an SBOM** — each archive ships with a Software Bill of
  Materials generated by [syft](https://github.com/anchore/syft).

### Verifying a release

```bash
# 1. Verify the checksum signature (binds checksums.txt to our CI pipeline)
cosign verify-blob \
  --certificate checksums.txt.pem \
  --signature checksums.txt.sig \
  --certificate-identity-regexp 'https://github.com/sentra-language/sentra/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  checksums.txt

# 2. Verify the artifact against the signed checksums
sha256sum --check --ignore-missing checksums.txt
```

### Building from source

If you prefer not to trust binaries at all:

```bash
git clone https://github.com/sentra-language/sentra.git
cd sentra
go build ./cmd/sentra
```

Builds use `CGO_ENABLED=0` and Go modules with `go.sum` integrity pinning.

## Reporting a Vulnerability

Please report security vulnerabilities privately via
[GitHub Security Advisories](https://github.com/sentra-language/sentra/security/advisories/new)
rather than opening a public issue. We will acknowledge reports within 72
hours.

Please include a proof of concept and the affected version or commit where
possible.

## Supported Versions

Sentra is pre-1.0: only the latest release receives security fixes.
